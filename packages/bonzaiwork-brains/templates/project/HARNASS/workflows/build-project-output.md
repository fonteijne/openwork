# Build an answer or deliverable from the project wiki

## 1. Clarify the request

Identify the question or deliverable, intended audience, purpose, desired format, and scope. Ask a focused clarification only if ambiguity would materially change the result. Do not invent a project position or decision.

## 2. Ground in compiled knowledge

Read `wiki/index.md`, `wiki/glossary.md`, and relevant wiki pages first. Apply approved preferred terms and project-specific meanings consistently. Do not change direct quotations, hide source-specific terminology, or assume a disputed term has been resolved. Use raw sources to verify important, disputed, or time-sensitive claims, or when the wiki does not adequately support the request. Treat raw material as evidence to inspect, not a shortcut around the wiki. Note stale, provisional, or disputed status.

## 3. Draft transparently

Separate sourced facts, synthesis, and recommendations. Link relevant wiki pages and, where useful, underlying raw sources. State gaps and disagreements rather than filling them with invented certainty. Tailor language to the requested audience without changing evidence strength.

## 4. Save and verify

For durable requested deliverables, save in `output/` using a descriptive, dated filename where appropriate. Re-open the result, verify links and factual support, and report limitations or decisions that need human review. Do not create a file when the user only asked for an answer in chat.
